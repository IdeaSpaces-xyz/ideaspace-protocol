# schema/

The machine-readable, language-neutral contract — so non-TypeScript runtimes can conform without importing the reference library.

Present (v0.33.0, provisional; time is something a folder keeps, by placement under `_threads/` or by `keeps_time: true` in its own Agreement, and entries set its state by one rule, the newest readable entry's value, with `closed` as the named exception; a Thread's place in the tree is `parent`, one post reference set by its newest post, and what it is about is `about`, typed links; a Thread's current Map is the Map of its newest post that carries one; `as_of`, `since` and `newest` select entries in time; capability options sit beside the ladder; hosted Thread ids are opaque in length; Content look pages directory handles and resolves an entry by id at a selected root/pin; Map v3 keeps live Space Maps without mandatory pins/depths):

- [`frontmatter.schema.json`](frontmatter.schema.json) — the ordinary Note Layer 1 leaf. Fields: `name`, `summary`, `attached_to` (single typed `<type>:<id>` subject link), `tags`, and the Agreement-only `agreement` and `keeps_time`. Nothing strictly required (absent = drift, not error); `additionalProperties` allowed (extensible). Do not apply this schema to Thread Agreements.
- [`time.md`](time.md) — a folder that keeps time: which files are entries and which stay Notes, immutable entries and their fields, code-unit order and the opening, the reply DAG, `correction`/`supersedes` and `mark` folding, who an entry asks (`to`), the one state rule (`parent`, `about`, `closed`, the current Map, a `reframe`'s `name` and `summary`) and the `closed` exception, the legacy `snapshot` and `closure` kinds, the README as a view, the `as_of`/`since`/`newest` selections, and entry look and paging.
- [`thread-agreement.schema.json`](thread-agreement.schema.json) — separate optional Thread Agreement frontmatter; new writers validate its post-target grammar (`parent`, legacy `attached_to`), while readers tolerate a malformed existing value with a warning. Since 0.33.0 the current parent is set by posts; the Agreement field is the fallback kept during the compatibility window, read before the opening post's origin. Only a post reference is a tree edge. See [`threads.md`](threads.md).
- [`agent-contract.md`](agent-contract.md) — selectable Foundation/Agreement frames, Agreement full-load declarations, floor orientation, root composition, prompt placement, skills, extensions, and conformance.
- [`repository-path.md`](repository-path.md) — pure lexical classification of Markdown knowledge, core `_agent`, ordinary paths, reserved Git state, and the first opaque extension owner.
- [`extensions.md`](extensions.md) — the bounded documentation contract for a named extension, its maturity path, extension-owned format evolution, and `_assets/` as the worked example.
- [`assets.md`](assets.md) — exact `_assets/` supporting payload, ordinary relative resolution from the containing Markdown file, one pure lexical operation, and the no-search/no-fallback boundary.
- [`root-identity.md`](root-identity.md) — optional `root_node_id` declaration in either root entrypoint, current and legacy forms, one-minter lifecycle, pure evidence states, and lazy convergence.
- [`maps.md`](maps.md) — provisional opt-in `map` frontmatter: ordered repository positions and open addresses, canonical repo URLs, optional root pins and representation ceilings, optional root names and `@root//position` addresses, bounded recursive walking, and safe degradation.
- [`map-projection.md`](map-projection.md) — pure tree/root-handle projection into Map members with observed disclosure, private presentation sidecars, deterministic rendering, and an explicit portability gate.
- [`content-awareness.md`](content-awareness.md) — portable read-only selectable-frame and reference-focus results, exact loaded representations/revisions, floor orientation, prompt placement, and canonical full or placement-selective rendering.
- [`content-look.md`](content-look.md) — one local Note or Content directory at a canonical Map rung beneath a reference-only frame, with rootless projection and deterministic rendering.
- [`markdown-inspection.md`](markdown-inspection.md) — portable progressive-disclosure reads for one Markdown document: summary, ATX outline, or an explicitly selected section.
- [`local-effects.md`](local-effects.md) — the language-neutral `write_markdown`, `commit_paths`, and `path_revision` contract: per-path revision CAS, root/symlink/ignore safety, frontmatter preservation, exact commits, and typed partial failure.
- [`workspace-handles.md`](workspace-handles.md) — neutral root summaries and immediate-child repository handles for local workspace awareness.
- [`trailers.md`](trailers.md) — the Change layer: commit trailers (`Op`, `Conversation`, `Change-Id`, …), the `Change-Id` format, and the not-a-superproject stance.
- [`verbs.md`](verbs.md) — the four verbs `map`, `look`, `post` and `write`: the one `ideaspaces` namespace and its spelling per route, what each does locally and remotely, old names as aliases until 1.0, one `write` (any file, refuses an entry, history only when asked), the answer shape (`said` first, then the closed set of Git `facts`, a refusal's `reason_code` and `next` as a verb call), `post`'s request kinds and the three guards on the acts that reach other people, lists (`map` from the account, an org or a person: fields only, seeing is not reaching, no lists for listeners, handles by shape) and `look`'s `access`, where the verbs write history, and the table of words AX owns.
- [`surface-state.md`](surface-state.md) — shared surface state: the interop conventions surfaces derive identically to coexist (`~/.ideaspaces/` caches, `refs/ideaspaces/` markers) — the underscore-namespace move applied outside the content tree.

These make the normative shape and its portable interoperability conventions language-neutral. `repository-path.md` defines only the generic negative boundary: unknown extension payload stays quiet and opaque, while Git state and explicit selection remain separate mutation facts. `extensions.md` explains how a named convention publishes semantics without adding discovery or runtime machinery. `assets.md` names one supporting-material role and pure resolver without adding storage or rendering policy. `root-identity.md` adds only validation when a selected root entrypoint declares the optional field; absence remains valid. `maps.md` adds no base repository-conformance requirement: unaware readers ignore the block, and malformed Map guidance is projection drift rather than a rejected Note. `map-projection.md` adapts already-read local handles without making them portable by assertion. `content-awareness.md`, `content-look.md`, `markdown-inspection.md`, `workspace-handles.md`, and `surface-state.md` do not add repository-conformance requirements beyond [`../SPEC.md`](../SPEC.md). `local-effects.md` applies only to tools that claim local-effect conformance; it does not require every ideaspace reader to mutate repositories. `verbs.md` applies only to hosts that offer the four verbs; it fixes how an act is asked for and answered, not what a service does with it. **Provisional and public** — the attach-type namespace especially is expected to grow, and breaking changes remain possible before 1.0.

- [`access.md`](access.md) — canonical capabilities, levels, grant statements, migration and Open questions.
